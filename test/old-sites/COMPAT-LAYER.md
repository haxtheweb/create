# Compatibility layer inventory

What the backends do so that a site made by an older release keeps working,
stated as what must stay true, with the fixture and the step of
[`run.cjs`](run.cjs) that fail when it stops being true
([haxtheweb/issues#3175](https://github.com/haxtheweb/issues/issues/3175)).

Rules for this file:

- A row is an invariant, not a history: it says what holds for every site,
  whatever release made it.
- A new self-healing path in a backend comes with a fixture that has the old
  shape, a step that asserts the outcome, and a row here. If no fixture can
  carry the old shape, the row goes under [Not reached by a fixture](#not-reached-by-a-fixture)
  with the unit test that guards it.
- Both backends keep the same invariant. haxcms-nodejs is under `src/lib/`,
  haxcms-php under `system/backend/php/lib/`.

## Not reached by a fixture

These are kept by the backends and guarded by their own unit tests. No
fixture has the old shape, because the releases the fixtures were made with
did not write it into a new site, so this check would not notice if one of
them stopped working on a whole site.

| Invariant                                                                                                                                                                       | Where it is kept                                         | Guarded by                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| Item values an older site stored loosely (`"1"` / `""` flags, numbers as text, comma separated tags) are read with the same meaning, and every save writes the canonical types. | `JSONOutlineSchema.normalizeItemValues` in both backends | `test/unit/json-outline-schema.test.cjs` (haxcms-nodejs), `tests/Unit/JSONOutlineSchemaTest.php` (haxcms-php)                         |
| A page whose `metadata.files` entries are objects without a uuid is listed without error; the entries take the current form the next time the page is saved.                    | `FileStorage` in both backends                           | `test/unit/pageSaveFilesTracking.test.cjs` (haxcms-nodejs), `tests/Unit/SocialShareImageTest.php` (haxcms-php, reading the old shape) |

Outside this check, because they belong to the install and not to a site: a
stored plain-text password is verified and replaced by a hash at the next
successful login, and a refresh-token store in the older shape is read so
live sessions survive an update. Both are guarded by the backends' auth
unit tests.
