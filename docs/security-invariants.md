# Security invariants

Rules this codebase keeps. Each inline `// Security (<name>)` comment in `src/`
marks a place where one of these rules is enforced; the name is the row below.
New code that touches the same surface follows the rule, and a change that
weakens one needs a matching test change in the listed suite.

Keep this table in step with the comments:
`grep -rhoE "Security \([^)]+\)" src | sort -u`.

| Invariant                   | Rule                                                                                                                                                                                                                                              | Enforced by                                                                                                        | Tested in                                                                     |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------- |
| `ssrf-guarded-fetch`        | Every remote fetch (site.json, item locations, import sources, scraped pages, image URLs) goes through haxcms-nodejs' `safeFetch`; never a raw `fetch`.                                                                                           | `safeFetch`, `isSSRFError` in `src/lib/site-security.js`; importers in `src/lib/programs/site.js`                  | `test/unit/site-security.test.cjs`                                            |
| `sanitize-remote-html`      | HTML that came from a remote or scraped source is sanitized before it is written into a page file.                                                                                                                                                | `sanitizeIfString` in `src/lib/site-security.js`                                                                   | `test/unit/site-security.test.cjs`                                            |
| `safe-local-paths`          | Local import paths are canonicalized and null bytes are rejected before any filesystem access.                                                                                                                                                    | `resolveLocalPath` in `src/lib/site-security.js`                                                                   | `test/unit/site-security.test.cjs`, `test/unit/security-helpers-fuzz.test.js` |
| `no-shell-strings`          | Child processes get an argument array and a `cwd`; no `exec("cd ${dir} && ...")` strings carry user values. The security lint gate fails on interpolated `exec()`.                                                                                | `runCommand` / `interactiveExec` in `src/lib/utils.js`; `eslint.security.config.mjs`                               | `test/unit/security-lint-gate.test.cjs`                                       |
| `validated-cli-options`     | Option values that reach a command line or the filesystem (`--root`, `--source`, `--destination`, `--exclude`, `--git-repo`, `--domain`, the on-disk surge `CNAME`) are checked for shell metacharacters at the option boundary and again at use. | `rejectShellMetacharacters`, `validateDomain` in `src/lib/utils.js`                                                | `test/unit/utils.test.cjs`, `test/unit/security-helpers-fuzz.test.js`         |
| `no-leading-dash`           | A value that starts with `-` is refused where a CLI (rsync, git, surge, netlify, vercel) would read it as an option; rsync paths are preceded by `--` and publish targets use `--site=` / `--name=` forms.                                        | `rejectLeadingDash`, `validateDomain` in `src/lib/utils.js`                                                        | `test/unit/utils.test.cjs`                                                    |
| `npm-client-allowlist`      | `--npm-client` is one of `npm`, `yarn`, `pnpm`, checked early and re-checked where it is used.                                                                                                                                                    | `validateNpmClient` in `src/lib/utils.js`                                                                          | `test/unit/utils.test.cjs`                                                    |
| `strict-names`              | Site, element and theme names are slugs (`hasNameSpecialCharacters`) on both the prompt and the non-interactive path, because they become file paths, import lines and child-process `cwd`.                                                       | `hasNameSpecialCharacters`, `validateWebcomponentName` in `src/lib/utils.js`                                       | `test/unit/utils.test.cjs`, `test/unit/security-helpers-fuzz.test.js`         |
| `validated-github-targets`  | GitHub owner, repo and `--author` values are validated before they form clone or fork targets.                                                                                                                                                    | `isValidGithubOwner`, `isValidGithubRepo` in `src/lib/programs/party.js`                                           | `test/unit/utils.test.cjs`                                                    |
| `twig-constant-allowlist`   | Twig `constant()` resolves from a static allowlist, never from `process.env` or globals.                                                                                                                                                          | `src/lib/programs/site.js` (template rendering)                                                                    | `test/unit/site-security.test.cjs`                                            |
| `loopback-dev-server`       | The no-login local server (`HAXCMS_DISABLE_JWT_CHECKS`) is only ever spawned with `HAXCMS_HOST=127.0.0.1` unless the user set `HAXCMS_HOST` explicitly.                                                                                           | `localHaxcmsServerEnv` in `src/lib/programs/site.js`                                                               | `test/unit/site-haxcms-bin.test.cjs`                                          |
| `confirmed-pinned-installs` | Anything installed or run from the registry on the user's behalf (publish CLIs, the haxcms-nodejs fallback, schema validators) is pinned to a version and confirmed first unless `--y` or no TTY.                                                 | `confirmPublishCliInstall`, `execNpxHaxcmsNodejsFallback` in `site.js`; `confirmNpxValidator` in `audit-schema.js` | `test/unit/audit-schema.test.cjs`, `test/unit/site-command-more.test.cjs`     |
| `in-process-converters`     | Document converters run in-process through haxcms-nodejs route handlers (`invokeRoute`); the deprecated `@haxtheweb/open-apis` cloud dependency is not used.                                                                                      | `src/lib/programs/site.js`                                                                                         | converter tests under `test/unit/`                                            |
| `template-allowlist`        | `--template` is one of the shipped template directories, and the scaffold is verified to exist after the copy.                                                                                                                                    | `validateTemplateName`, `listTemplateNames` in `src/lib/utils.js`                                                  | `test/unit/utils.test.cjs`                                                    |
| `scaffolded-ci-pinned`      | Workflows shipped into new projects SHA-pin every action, use `npm ci`, set `persist-credentials: false`, and grant `contents: write` only to the deploy job.                                                                                     | `src/templates/**/_github/workflows/*.yml`                                                                         | `test/unit/scaffold-workflows-security.test.cjs`                              |
